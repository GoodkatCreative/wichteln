# Wichtel-Seite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine statische Wichtel-Seite für GitHub Pages: Organisator lost aus und verteilt persönliche Links, jeder Empfänger sieht per Knopfdruck, wen er beschenkt.

**Architecture:** `index.html` zeigt ohne `#`-Anker die Organisator-Ansicht, mit Anker die Empfänger-Ansicht. Die reine Logik (Namen lesen, auslosen, Link kodieren/dekodieren) liegt in `wichtel.js`, das sowohl im Browser als klassisches Script lädt als auch per `module.exports` in Node testbar ist.

**Tech Stack:** HTML, CSS, Vanilla-JS. Keine Abhängigkeiten, kein Build. Tests mit `node --test` (eingebaut).

**Spec:** `docs/superpowers/specs/2026-11-21-wichteln-design.md`

## Global Constraints

- Keine Abhängigkeiten, kein Server, kein Build-Schritt. Muss als statische Dateien auf GitHub Pages laufen.
- Budget-Text exakt: **Budget: 50 Euro** (fett, auf der Empfänger-Seite).
- Empfänger-Texte exakt: „Hallo <Name>!“, Knopf „🎁 Namen zeigen“, „Du beschenkst:“, „Diesen Link einfach wieder öffnen, um nachzusehen.“
- Niemand zieht sich selbst. Keine Ausschluss-Regeln.
- Die Zuordnung wird dem Organisator nicht angezeigt.
- Schrift mind. 28px, hoher Kontrast, ein Hauptknopf pro Bildschirm, mobil bedienbar ohne Zoomen oder seitliches Scrollen.
- Daten nur im Anker (`#…`), nie im Query-String.

## Review Focus

1. **Umlaute/Sonderzeichen in Namen** („Jürgen“, „Anne-Marie“, Emoji): Link muss den Namen exakt wiederherstellen. → Test in Task 1.
2. **Abgeschnittener oder kaputter Link** (WhatsApp/Mail kürzt): Empfänger sieht freundlichen Hinweis „Dieser Link funktioniert leider nicht. Bitte frag nach einem neuen Link.“ statt leerer Seite. → Test in Task 1, Prüfung in Task 2.
3. **Doppelte Namen** (zweimal „Oma“, auch „oma“ vs. „Oma“): Auslosen wird verweigert mit Hinweis „Jeder Name darf nur einmal vorkommen.“ → Test in Task 1.
4. **Leerzeilen und Leerzeichen** im Eingabefeld: werden ignoriert bzw. getrimmt. → Test in Task 1.
5. **Weniger als 3 Namen**: Auslosen verweigert mit „Bitte mindestens 3 Namen eingeben.“ (bei 2 wäre die Zuordnung für beide offensichtlich). → Test in Task 1.

### Task 1: Logik (`wichtel.js`) mit Tests

**Files:**
- Create: `wichtel.js`
- Test: `wichtel.test.js`

**Interfaces:**
- Produces (global im Browser, `module.exports` in Node):
  - `parseNames(text: string) -> { names: string[] } | { error: string }` – teilt an Zeilenumbrüchen, trimmt, entfernt Leerzeilen; Fehler bei < 3 Namen oder Duplikaten (Vergleich ohne Groß-/Kleinschreibung). Fehlertexte exakt wie in Review Focus 3 und 5.
  - `draw(names: string[], rand = Math.random) -> Array<{ giver: string, receiver: string }>` – Fisher-Yates mischen, dann beschenkt jeder den Nächsten im Kreis.
  - `encodeHash(giver: string, receiver: string) -> string` – liefert `"#" + base64url(UTF-8-JSON {g, r})`. UTF-8 über `TextEncoder`, base64 über `btoa`, dann `+`→`-`, `/`→`_`, `=` entfernen.
  - `decodeHash(hash: string) -> { giver: string, receiver: string } | null` – Umkehrung; `null` bei jedem Fehler oder fehlenden Feldern.

- [ ] **Step 1: Failing tests schreiben** (`wichtel.test.js`, `node:test` + `node:assert/strict`, `require('./wichtel.js')`)

```js
test('parseNames trimmt und ignoriert Leerzeilen', () => {
  assert.deepEqual(parseNames(' Erna \n\nKlaus\n  Jürgen  \n'), { names: ['Erna', 'Klaus', 'Jürgen'] });
});
test('parseNames verweigert weniger als 3 Namen', () => {
  assert.deepEqual(parseNames('Erna\nKlaus'), { error: 'Bitte mindestens 3 Namen eingeben.' });
});
test('parseNames verweigert Duplikate ohne Groß/klein', () => {
  assert.deepEqual(parseNames('Oma\nKlaus\noma'), { error: 'Jeder Name darf nur einmal vorkommen.' });
});
test('draw: jeder gibt und bekommt genau einmal, nie sich selbst', () => {
  const names = ['A', 'B', 'C', 'D', 'E'];
  for (let i = 0; i < 200; i++) {
    const pairs = draw(names);
    assert.equal(pairs.length, 5);
    assert.deepEqual(pairs.map(p => p.giver).sort(), names);
    assert.deepEqual(pairs.map(p => p.receiver).sort(), names);
    for (const p of pairs) assert.notEqual(p.giver, p.receiver);
  }
});
test('encode/decode erhält Umlaute, Bindestrich und Emoji', () => {
  const h = encodeHash('Anne-Marie', 'Jürgen 🎅');
  assert.match(h, /^#[A-Za-z0-9_-]+$/);
  assert.deepEqual(decodeHash(h), { giver: 'Anne-Marie', receiver: 'Jürgen 🎅' });
});
test('decodeHash gibt null bei kaputtem oder leerem Link', () => {
  assert.equal(decodeHash(''), null);
  assert.equal(decodeHash('#'), null);
  assert.equal(decodeHash('#kaputt!!'), null);
  assert.equal(decodeHash(encodeHash('Erna', 'Klaus').slice(0, 8)), null);
});
```

### Task 2: Seite (`index.html`) – Organisator- und Empfänger-Ansicht

**Files:**
- Create: `index.html` (lädt `<script src="wichtel.js">`, eigenes CSS und Script inline)

**Interfaces:**
- Consumes: `parseNames`, `draw`, `encodeHash`, `decodeHash` aus Task 1.

**Verhalten:**
- Beim Laden: `decodeHash(location.hash)`.
  - Anker leer → **Organisator-Ansicht:** Überschrift „Wichteln – Auslosen“, `<textarea>` mit Label „Alle Namen, ein Name pro Zeile:“, Knopf „Auslosen“. Bei `{error}` den Fehlertext groß über dem Knopf anzeigen. Bei Erfolg: Eingabe ausblenden, je Person eine Zeile „Link für <giver>“ + Knopf „Link kopieren“. Link = `location.origin + location.pathname + encodeHash(giver, receiver)`. Kopieren via `navigator.clipboard.writeText`; danach Knopftext für 2 s „✓ Kopiert“. Der Empfängername erscheint nirgends im sichtbaren Text oder in `title`-Attributen.
  - Anker vorhanden, `decodeHash` ok → **Empfänger-Ansicht:** „Hallo <giver>!“ und Knopf „🎁 Namen zeigen“. Nach Klick: „Du beschenkst:“, darunter der Empfängername in Großbuchstaben-Optik (sehr groß), darunter `<strong>Budget: 50 Euro</strong>`, darunter „Diesen Link einfach wieder öffnen, um nachzusehen.“
  - Anker vorhanden, `decodeHash` gibt `null` → Text „Dieser Link funktioniert leider nicht. Bitte frag nach einem neuen Link.“
- Namen immer per `textContent` einsetzen, nie per `innerHTML` (Namen sind Nutzereingaben).
- `<html lang="de">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`, Grundschrift ≥ 28px, Knöpfe ≥ 64px hoch und volle Breite auf dem Handy, Kontrast ≥ 7:1.

- [ ] **Step 1: `index.html` bauen** wie oben beschrieben.

- [ ] **Step 2: Lokal starten**

Run: `npx --yes http-server -p 8080 .` (oder `python -m http.server 8080`)
Expected: Seite unter `http://localhost:8080/` erreichbar.

- [ ] **Step 3: Im Browser über echte Eingaben prüfen** (Tippen und Klicken, nicht Funktionen direkt aufrufen)
  - „Erna\nKlaus“ eintippen, „Auslosen“ klicken → „Bitte mindestens 3 Namen eingeben.“
  - „Oma\nKlaus\noma“ → „Jeder Name darf nur einmal vorkommen.“
  - „Erna\nKlaus\nJürgen\nAnne-Marie“ → 4 Zeilen „Link für …“, kein Empfängername sichtbar.
  - „Link kopieren“ klicken → Knopf zeigt „✓ Kopiert“; kopierten Link in neuem Tab öffnen → „Hallo <Name>!“, Klick auf „🎁 Namen zeigen“ → Empfängername + fett „Budget: 50 Euro“.
  - Link mit abgeschnittenem Anker öffnen → Fehlertext aus Review Focus 2.
  - Fenster auf 375px Breite → kein seitliches Scrollen, Knöpfe volle Breite.
